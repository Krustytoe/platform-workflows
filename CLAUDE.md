# platform-workflows

Reusable GitHub Actions workflows and composite actions for Terraform plan/apply, Trivy security scanning, and OIDC authentication to AWS (commercial + GovCloud) and Azure. Other repos consume them by pinned SHA or release tag, so every input, output, and secret is public interface.

## Layout

- `.github/workflows/terraform-plan.yml` — reusable (`workflow_call`): fmt -check → init → validate → tflint → plan; posts the plan as a PR comment and job summary; optionally uploads the plan artifact (1-day retention). Output: `has_changes`.
- `.github/workflows/terraform-apply.yml` — reusable: applies the exact saved plan inside the GitHub environment passed as the `environment` input (the approval gate).
- `.github/workflows/trivy-scan.yml` — reusable: Trivy `fs` / `config` / `image` scan, uploads SARIF to the Security tab.
- `actions/aws-oidc-auth/action.yml`, `actions/azure-oidc-auth/action.yml` — composite OIDC auth actions (no long-lived keys or client secrets).
- `actions/terraform-setup/action.yml` — composite action installing Terraform and tflint, then `tflint --init`.
- `.github/workflows/ci.yml` — actionlint on every PR and push to `main`.
- `.github/workflows/zizmor.yml` — zizmor static security analysis of the workflows, SARIF to the Security tab. `.github/workflows/scorecard.yml` — weekly OpenSSF Scorecard.
- `.github/workflows/release-please.yml`, `release-please-config.json`, `.release-please-manifest.json`, `CHANGELOG.md` — releases.
- `.github/workflows/dependabot-auto-merge.yml`, `.github/dependabot.yml` — weekly action bumps for `/` and `/actions/*`; patch/minor auto-merge, majors left for review.
- `README.md` — usage docs with input/output/secret tables for every workflow and action.

## Commands

CI runs actionlint 1.7.12. Run the same locally from the repo root:

```bash
actionlint -color
```

actionlint also runs shellcheck on `run:` blocks when shellcheck is installed. To test a workflow change end to end, push the branch and call the workflow from a test repo pinned to the branch's commit SHA, never `@main`.

## Conventions

- PR titles must be Conventional Commits (`feat:`, `fix:`, `docs:`, `ci:`, `chore:`, `feat!:` for breaking changes). PRs are squash-merged; release-please uses the title to pick the version and write `CHANGELOG.md`.
- Inputs, outputs, and secrets are the public interface. Update the README tables when they change, and use `!` in the PR title for anything that breaks existing callers.
- Pin every third-party action to a full commit SHA with the version as a trailing comment (`uses: org/action@<sha> # v1.2.3`) so Dependabot can bump it.
- **Reusable workflows must not call this repo's own composite actions.** A workflow can't pin its own repo to its own SHA, so inline those steps (third-party actions SHA-pinned) and keep them in sync with `actions/*/action.yml`.
- README usage examples end with `# x-release-please-version`; release-please rewrites the version in `README.md` on release. Keep that marker on version-pinned `uses:` lines.
- Declare least-privilege `permissions:`; request `id-token: write` only where OIDC is used.
- Workflow and action input names use `snake_case`.
- One concern per PR.

## Guardrails

- **No long-lived cloud credentials.** Authenticate only through OIDC (`aws-oidc-auth`, `azure-oidc-auth`, or the equivalent inlined steps).
- **The apply approval gate lives in GitHub environments**, not workflow logic. Do not add code paths that bypass the environment gate or apply a plan other than the reviewed artifact.
- Treat plan files as sensitive: they can contain plaintext secrets. Keep artifact retention short and never print plan files or credentials beyond what the workflows already emit.
- **No secrets in the repo.** No tokens, keys, account/subscription/tenant IDs, or internal hostnames in examples; use obvious placeholders.
- Never reference this repo as `@main` from callers or examples; callers pin by release tag or SHA.
- Never trigger an apply or any deployment without explicit human approval.
- Report security issues privately per `SECURITY.md`, never in a public issue.
- **Generated agent files.** `AGENTS.md`, `CLAUDE.md`, and `.gemini/settings.json` at the repo root are generated by Ruler from `.ruler/`. Edit `.ruler/AGENTS.md`, then run `npx @intellectronica/ruler@0.3.46 apply`. Never hand-edit the generated files.

## Definition of done

- `actionlint -color` passes with no findings.
- Any new or bumped third-party action is pinned to a full SHA with a version comment.
- Inlined steps in reusable workflows match `actions/*/action.yml`.
- README input/output/secret tables updated if the interface or behaviour changed.
- No secrets, account/subscription/tenant IDs, or internal hostnames in the diff.
- PR title is a Conventional Commit, breaking changes are marked with `!` and explained, and the PR template's "How it was validated" lists the commands run and their results.
